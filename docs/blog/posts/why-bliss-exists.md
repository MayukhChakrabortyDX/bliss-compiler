# Why Bliss exists

Bliss started with a simple question: what would systems programming look like if we were willing to reconsider the assumptions underneath it?

## The familiar path

Systems languages have accumulated powerful conventions around memory, ownership, syntax, and program structure. Those conventions are useful, but they also constrain the space of designs we tend to consider.

## A different starting point

Bliss is an exploration of those foundations rather than an attempt to reproduce an existing language with different syntax.

## Built in public

The compiler and language are being developed together. Experiments, failures, parser work, and design changes are part of the project rather than hidden implementation details.
